RAG (Retrieval-Augmented Generation) 기술 가이드

RAG란 무엇인가?
RAG는 대규모 언어 모델(LLM)의 응답 품질을 향상시키기 위해, 외부 지식 소스에서 관련 정보를 검색(Retrieval)하여 생성(Generation)에 활용하는 기술입니다.

LLM의 한계:
- 학습 데이터의 시점 이후 정보를 알지 못합니다 (Knowledge Cutoff).
- 학습하지 않은 도메인 전문 지식에 대해 정확한 답변을 하기 어렵습니다.
- 환각(Hallucination) 현상으로 사실과 다른 정보를 그럴듯하게 생성할 수 있습니다.

RAG의 동작 원리:
1. 문서 준비 (Ingestion)
   - 원본 문서를 텍스트로 변환합니다 (PDF 파싱, HTML 파싱 등).
   - 텍스트를 적절한 크기의 청크(Chunk)로 분할합니다.
   - 각 청크를 임베딩 모델로 벡터화합니다.
   - 벡터를 벡터 데이터베이스에 저장합니다.

2. 검색 (Retrieval)
   - 사용자 질의를 동일한 임베딩 모델로 벡터화합니다.
   - 벡터 데이터베이스에서 유사도가 높은 청크를 검색합니다.
   - 검색 결과를 관련도 순으로 정렬합니다.

3. 생성 (Generation)
   - 검색된 관련 청크를 프롬프트에 컨텍스트로 삽입합니다.
   - LLM이 컨텍스트를 참조하여 답변을 생성합니다.
   - 출처(Source) 정보를 함께 제공합니다.

청킹 전략:
- 고정 크기 청킹: 일정 토큰 수(예: 300토큰)로 분할합니다. 구현이 간단하지만 문맥이 끊길 수 있습니다.
- 시맨틱 청킹: 문단이나 섹션 단위로 의미 있게 분할합니다. 문맥 보존이 우수합니다.
- 계층적 청킹: 부모-자식 관계를 유지하며 분할합니다. 요약과 상세 정보를 함께 활용할 수 있습니다.

임베딩 모델 비교:
- Amazon Titan Embeddings V2: 1024차원, AWS 네이티브 통합 우수, Bedrock Knowledge Bases 기본 모델.
- OpenAI text-embedding-3-small: 1536차원, 높은 검색 정확도, 별도 API 키 필요.
- Cohere Embed: 다국어 지원 우수, 1024차원, Bedrock에서 직접 사용 가능.

벡터 데이터베이스 선택지:
- Amazon OpenSearch Serverless: Bedrock Knowledge Bases와 자동 통합, 서버리스, 관리 부담 최소.
- Amazon Aurora PostgreSQL (pgvector): 기존 RDS 인프라 활용 가능, SQL 기반 쿼리.
- Pinecone: 벡터 검색 전용 SaaS, 빠른 검색 속도, 별도 계정 필요.
- FAISS: 오픈소스, 인메모리 기반, 소규모 데이터셋에 적합, 별도 인프라 필요.
